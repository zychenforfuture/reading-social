# 代码质量提升计划

## 1. 目标
- 提升可读性、可维护性和可回归能力
- 建立质量门禁并强制执行
- 将质量治理从人治变为机制化

## 2. 现状问题
- 测试覆盖不均衡，路由与工具测试多、业务逻辑测试偏少
- 代码重复（参数处理、权限判断、错误返回）
- 缺少统一复杂度控制和重构节奏

## 3. 行动项
- 短期（1-2 周）
  - 在 CI 增加质量门禁：lint、typecheck、test 必须通过
  - 增加覆盖率阈值（先按模块设置最低门槛）
  - 统一代码风格与提交规范（提交信息、PR 检查项）
- 中期（3-6 周）
  - 为 Service 层补齐单元测试和集成测试
  - 引入测试数据工厂与测试夹具，降低编写成本
  - 清理高重复片段，抽取通用中间件和 helper
- 长期（6-10 周）
  - 设立质量周报：覆盖率、失败率、平均修复时长
  - 定期执行热点文件重构机制（按变更频率和缺陷率排序）

## 4. 里程碑与验收
- M1：CI 门禁启用且稳定运行
- M2：关键业务模块（文档/评论/通知）测试闭环
- M3：建立持续质量看板
- 验收指标：
  - 核心模块测试覆盖率 >= 80%
  - 线上回归缺陷率下降 30%
