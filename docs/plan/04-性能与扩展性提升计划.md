# 性能与扩展性提升计划

## 1. 目标
- 降低高频接口延迟，提升并发稳定性
- 建立可观测能力，支持容量规划
- 明确 API、Worker、数据库的扩展路径

## 2. 现状问题
- 热点接口缓存策略不系统
- 异步任务优先级、重试与死信策略需要标准化
- 缺少完整性能基线和压测结论

## 3. 行动项
- 短期（1-3 周）
  - 建立性能基线（P50/P95/P99、错误率、队列积压）
  - 为高频列表接口增加分页与缓存策略
  - 梳理数据库索引命中率和慢查询清单
- 中期（4-8 周）
  - 完善 BullMQ：优先级、重试退避、死信队列
  - 引入连接池与并发参数调优手册
  - 优化评论和通知查询链路，避免 N+1 查询
- 长期（8-12 周）
  - 建立弹性扩容策略（API/Worker 水平扩容）
  - 增加读写分离或只读副本评估报告

## 4. 里程碑与验收
- M1：完成性能基线和慢查询治理清单
- M2：Worker 队列策略与缓存策略上线
- M3：压测通过目标并形成容量模型
- 验收指标：
  - 核心接口 P95 延迟降低 30%
  - 峰值时段队列积压时间下降 40%
