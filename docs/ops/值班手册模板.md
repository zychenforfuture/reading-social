# 值班手册模板（On-call）

## 1. 值班目标
- 保障核心服务可用性
- 在故障发生时快速止损、恢复、同步信息
- 为事故复盘提供完整上下文

- 备值班人：
- 升级联系人（技术负责人/产品负责人）：
- 交接时间：

## 3. 值班前检查清单
- [ ] 熟悉本期发布变更与风险点
- [ ] 确认可访问生产日志与部署权限
- [ ] 确认告警渠道可用（IM/邮件/电话）
- [ ] 熟悉 Runbook：数据库、队列、Qdrant 故障排查

## 4. 值班期间巡检项
- 每 30-60 分钟巡检一次：
  - [ ] API 可用性与错误率
  - [ ] Web 可访问性
  - [ ] Worker 队列积压情况
  - [ ] PostgreSQL/Redis/Qdrant 连通性
- 每次巡检记录：时间、现象、结论、处理动作

## 5. 告警处理流程
1. 告警接收：确认告警来源、时间、影响范围
2. 快速分级：
   - P1：核心业务不可用 / 大面积故障
   - P2：部分功能异常 / 可绕行
   - P3：轻微异常 / 观察处理
3. 执行动作：
   - 先止损（降级、限流、回滚）
   - 再定位（日志、指标、最近变更）
   - 后修复（热修、重启、恢复）
4. 信息同步：每 10-15 分钟同步一次状态
5. 收尾：恢复后继续观察 30 分钟

## 6. 升级与协同机制
- P1 故障：立即升级技术负责人和产品负责人
- P2 故障：15 分钟未收敛则升级
- P3 故障：可在值班窗口内跟进并记录
