# 发布清单（Release Checklist）

## 1. 适用范围
- 适用于本项目 Web、API、Worker 的常规发布
- 适用于 Docker 部署模式（scripts/deploy.sh）

## 2. 角色与职责
- 发布负责人：执行发布、确认结果、组织回滚
- 审核人：确认发布窗口、变更范围、风险等级
- 值班人：发布后观察与应急响应

## 3. 发布前检查（必做）
- 代码与变更
  - [ ] 目标分支已合并完成，提交范围已冻结
  - [ ] 已确认变更说明（影响模块、风险点、回滚策略）
  - [ ] 数据库变更已评审（是否包含 DDL、是否可回滚）
- 质量门禁
  - [ ] lint 通过
  - [ ] typecheck 通过
  - [ ] 单元/集成测试通过
  - [ ] 关键路径冒烟测试通过（登录、文档读取、评论发布）
- 环境与资源
  - [ ] .env.production 参数完整且已复核
  - [ ] Docker 运行正常，磁盘空间充足
  - [ ] PostgreSQL/Redis/Qdrant 状态正常
- 备份与预案
  - [ ] 已执行数据库备份：./scripts/deploy.sh db-backup
  - [ ] 已明确本次回滚触发条件
  - [ ] 已指定回滚执行人

## 4. 发布执行步骤
1. 进入发布窗口，通知相关人员开始发布
2. 执行发布命令

```bash
./scripts/deploy.sh up
```

3. 若涉及强制重建，执行

```bash
./scripts/deploy.sh rebuild
```

4. 查看服务状态

```bash
./scripts/deploy.sh status
```

5. 检查日志（至少观察 5-10 分钟）

```bash
./scripts/deploy.sh logs
```

## 5. 发布后验证（必做）
- 系统级验证
  - [ ] API 健康检查通过（/health）
  - [ ] Web 页面可访问，核心路由正常
  - [ ] Worker 可消费任务，队列无异常堆积
- 业务级验证
  - [ ] 用户可登录
  - [ ] 文档可读取
  - [ ] 评论可发布并可见
  - [ ] 通知角标和列表可读取
- 稳定性观察
  - [ ] 错误日志未出现持续增长
  - [ ] 关键接口响应时间无显著退化
  - [ ] 基础组件连接正常（PostgreSQL/Redis/Qdrant）

## 6. 回滚触发条件
- 发布后 10 分钟内出现以下任一情况应立即回滚：
  - 核心链路不可用（登录、阅读、评论）
  - 错误率持续升高且无法在 10 分钟内缓解
  - 数据一致性风险（写入错误、任务重复/丢失）

## 7. 回滚步骤
1. 回滚代码到上一稳定版本（镜像或提交）
2. 重新拉起服务

```bash
./scripts/deploy.sh restart
```

3. 若涉及数据库问题，按备份执行恢复
4. 执行发布后验证同等流程，确认服务恢复
