# Runbook：队列堆积排查

## 1. 背景
- 适用场景：文档处理任务长时间排队、处理延迟明显升高
- 影响范围：文档状态长期停留 processing，跨文档检索能力更新滞后

## 2. 前置条件
- 可访问 Redis、Worker 服务日志
- 已确认 Qdrant 与 PostgreSQL 可用

## 3. 排查步骤
1. 检查 Worker 进程状态

```bash
pnpm --filter @collab/worker dev
# 生产查看
./scripts/deploy.sh status
```

2. 检查 Redis 连通性

```bash
docker exec collab-redis redis-cli --no-auth-warning -a "$REDIS_PASSWORD" ping
```

3. 检查 Worker 日志异常（连接中断、模型加载失败、Qdrant 写入失败）

```bash
./scripts/dev.sh logs
# 或
./scripts/deploy.sh logs
```

4. 判断是否单个大任务阻塞
- 查看最近上传文档体量
- 观察是否某个任务重复重试

## 4. 快速修复
- 重启 Worker，确认消费恢复
- 临时限制大文档上传
- 如为向量写入失败，先降级为仅分块与 SimHash，待 Qdrant 恢复后补偿

## 5. 验证步骤
- 上传一份小文档，确认状态在预期时间内由 processing 变为 ready
- 检查队列积压是否持续下降

## 6. 预防建议
- 给 BullMQ 配置重试退避与死信队列
- 增加队列积压告警阈值（任务数、等待时间）
- 对大文档处理设置优先级与并发上限
